# Architecture Journal

This directory records important architectural decisions made while building the NovaTrade frontend.

Entries are added only when a real architectural decision has been earned through implementation pressure.

The journal focuses on questions such as:

- What changed in NovaTrade?
- Why was the current design no longer sufficient?
- Which responsibility needed to move or become explicit?
- What was the smallest responsible response?
- Which alternatives were considered?
- What did we deliberately not add?
- What consequences did the decision create?

This is not a roadmap.

It does not describe future architecture in advance.

The journal should reflect the architecture that actually emerges from the implementation history.

## Guiding Principles

> No pattern without pressure.

> No infrastructure without a requirement.

> No architectural claim without proof.

## Rule for New Entries

Create a new journal entry only when there is an actual architectural decision worth recording.

Do not create one merely because a new chapter exists.
